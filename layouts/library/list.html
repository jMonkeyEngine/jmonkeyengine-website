Add the jmonkeyengine topic to your GitHub repository and it will be discovered periodically. To request discovery now, enter the repository below.

Advanced configuration

For exact coordinates, presentation images, and compatibility, add .github/jme.yaml:

# Optional. One entry per published root module.
# If omitted, coordinates are derived from Gradle project metadata.
mavenCoordinates:
  - provider: MAVEN_CENTRAL
    coordinates: com.example:my-module
  - provider: GITHUB_PACKAGES
    groupId: com.example
    artifactId: my-module-desktop
    # Optional: omit to use the latest published release.
    version: 1.0.0

# Providers: MAVEN_CENTRAL, GITHUB_PACKAGES, or JITPACK.
# JitPack versions are Git refs; the backend always emits the resolved full commit SHA.

# Optional presentation metadata.
displayName: My Module
description: A concise description for the library catalog.
homepage: https://example.com/my-module
coverImage: docs/cover.png
images:
  - docs/screenshot-1.png
  - https://example.com/screenshot-2.webp

# Optional when automatic dependency detection is not precise enough.
jmeCompatibility:
  minimum: 3.6.0-stable
  recommended: 3.7.0-stable
  maximum: 3.8.0-stable

# Optional. When omitted, native files in the module and its transitive
# dependencies determine compatibility. A pure Java module supports all.
platforms:
  - os: WINDOWS
    architectures: [X86_64, ARM64]
  - os: MACOS
    architectures: [X86_64, ARM64]
  - os: IOS
    architectures: [ARM64]

What does the score mean?

The score combines repository trust, artifact integrity, malware and vulnerability checks, code signals, documentation, and jMonkeyEngine compatibility. It helps compare modules, but it is not a security guarantee or a replacement for reviewing code before shipping it.
